# NeetCode: LeetCode 347, Top K Frequent Elements (Java)

Pattern: Arrays and hashing (#5)
Link: https://leetcode.com/problems/top-k-frequent-elements/

## Problem
You get an integer array `nums` and a number `k`. Return the `k` values that appear most often. The order of your result doesn't matter.

Example (made up):

    nums = [7, 4, 7, 9, 4, 7, 2], k = 2
    output: [7, 4]      // 7 appears 3 times, 4 appears twice

## Constraints that matter
- 1 <= nums.length <= 100,000
- -10,000 <= nums[i] <= 10,000 (negatives are possible)
- k is between 1 and the number of distinct values
- The answer is unique: no tie makes the top k ambiguous
- Follow-up target: do better than O(n log n)

Target: 30–40 min. Before coding, write your approach and its time/space complexity in a comment.

## Hints
Try on your own first. Open one at a time.

1. Split it into two jobs: find how often each value appears, then pick the k biggest by that number. Which structure does the first job in one pass?
2. You don't need every distinct value fully sorted. What could you keep that only ever holds the k best candidates seen so far, and which of them should be easiest to throw out?
3. For better than O(n log k): look at the range a frequency can take. Can a count be larger than `nums.length`? Think about what that lets you use as an array index.
