# NeetCode (Java): LeetCode 271, Encode and Decode Strings

Arrays and hashing #6
https://leetcode.com/problems/encode-and-decode-strings/

(This one may be locked behind LeetCode Premium. If so, solve it locally with your own small `main` or JUnit test.)

## Problem

You need to send a list of strings over a channel that only carries **one** string. Write two methods:

- `String encode(List<String> strs)` packs the list into a single string.
- `List<String> decode(String s)` rebuilds the original list from it.

The rule is that `decode(encode(x))` equals `x`: same strings, same order, same count. `decode` gets nothing except the encoded string, so don't pass information through fields or other shared state. Don't use a serialisation library.

## Example (my own)

Input: `["tea", "", "a,b;c", "42#x"]`
`encode` returns some single string (the format is your choice).
`decode` of that string returns `["tea", "", "a,b;c", "42#x"]`.

Also think about `[]` and `[""]`. They are different lists and must come back differently.

## Constraints that matter

- 0 to 200 strings (handle the empty list too)
- Each string has length 0 to 200
- Strings may contain **any** of the 256 extended ASCII characters, including whatever you might pick as a separator

Target: 30–40 min. Before coding, write your approach and its time/space complexity in a comment.

## Hints

**Hint 1:** Joining with a separator breaks as soon as a string contains that separator. Can the decoder know where a string ends without searching its content for a marker?

**Hint 2:** Tell the decoder something about each string *before* it reads that string.

**Hint 3:** Store each string's size in front of it. The size has a variable number of digits, so you need a way to mark where the number stops. Then think about why that marker is harmless if it also appears inside a string. In `decode`, move an index through the input yourself.
