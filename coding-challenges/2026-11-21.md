# React challenge: debounced search with race conditions (60–75 min)

Build a `UserSearch` component in TypeScript/JSX that searches users as you type, using a custom hook `useDebouncedValue`.

**Setup:** assume a function `searchUsers(query: string, signal: AbortSignal): Promise<User[]>` exists, where `User = { id: number; name: string }`. You can mock it with `fetch` against any public API or a fake that resolves after a random 100–1000 ms delay (the random delay is what exposes the race).

**Build:**
1. `useDebouncedValue<T>(value: T, delayMs: number): T` returns the value only after it has stopped changing for `delayMs`.
2. `UserSearch` has a text input and a results list. It searches with the debounced query (300 ms).
3. Show "Loading...", an error message, or "No results", depending on state. Empty query shows nothing and makes no request.
4. A slow, older response must never overwrite a newer one. Cancel stale requests with `AbortController`.
5. Results need stable `key`s (use `id`, not the index).

**Done looks like:**
- Typing "react" quickly fires one request, not five.
- Typing "ab", then quickly "abc", while "ab" is slower: the screen ends on the "abc" results.
- Unmounting mid-request causes no state update warning and no stray request.
- Clearing the input clears results and the error, and cancels anything in flight.
- An aborted request is not shown as an error.

**Behaviours a reviewer would test:** debounce timing, out-of-order responses, cleanup on unmount, error then retry by typing again, no stale closure over `query`, correct dependency arrays (no lint warnings suppressed).

Target: write your plan first in a comment (which state you need, and what the effect cleanup does).

## Hints
<details>
<summary>Hint 1</summary>
Debouncing is just "start a timer, and cancel it if the value changes before it fires". Which part of `useEffect` lets you cancel something when the dependency changes?
</details>
<details>
<summary>Hint 2</summary>
The race condition is the same shape as the debounce: each effect run needs a way to say "I'm obsolete now". Think about what you create inside the effect and what you call in its cleanup function.
</details>
<details>
<summary>Hint 3</summary>
Abort errors arrive as a rejected promise with `name === "AbortError"`. Decide deliberately what to do with them in your `catch`. Also check: what happens to `loading` and `error` state when the query becomes empty?
</details>
