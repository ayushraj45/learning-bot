# Coding challenge: current status of each order (SQL)

## Problem

An `order_events` table logs every status change for an order. The same order appears many times, and the feed sometimes delivers the same event twice. Write a query that returns, for each order, its **current status** (the latest event). Then extend it to report how many orders are currently in each status.

Table `order_events`:

| column      | type      |
|-------------|-----------|
| event_id    | int (PK)  |
| order_id    | int       |
| status      | text      |
| updated_at  | timestamp |

## Example

Input:

| event_id | order_id | status    | updated_at          |
|----------|----------|-----------|---------------------|
| 1        | 100      | placed    | 2026-11-01 09:00:00 |
| 2        | 100      | shipped   | 2026-11-02 10:00:00 |
| 3        | 101      | placed    | 2026-11-02 11:00:00 |
| 4        | 100      | delivered | 2026-11-04 12:00:00 |
| 5        | 102      | placed    | 2026-11-03 08:00:00 |
| 6        | 102      | cancelled | 2026-11-03 08:00:00 |

Part 1 output (order_id, status):

| order_id | status    |
|----------|-----------|
| 100      | delivered |
| 101      | placed    |
| 102      | cancelled |

Part 2 output (status, order_count):

| status    | order_count |
|-----------|-------------|
| cancelled | 1           |
| delivered | 1           |
| placed    | 1           |

## Constraints

- Millions of rows; one pass over the data is preferred.
- Orders 102-style ties exist (same `updated_at`): the result must be deterministic, and the higher `event_id` wins.
- Part 2 must be built on top of Part 1, not a separate scan of the raw table.
- Any standard SQL dialect (Postgres is fine).

## Hints

<details>
<summary>Hints</summary>

1. You need one row per order, so think about what ranks the events within each order.
2. A tie on the timestamp needs a second sort column.
3. Wrap Part 1 in a CTE, then group the CTE.

</details>
