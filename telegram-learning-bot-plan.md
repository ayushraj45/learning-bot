# Telegram Learning Bot — High-Level Plan

## 1. Goal

A personal learning system that:
- Sends bite-sized lessons to Telegram at set times on weekdays.
- Lets me ask follow-up questions about a lesson in Telegram and get fast answers.
- Prepares one daily coding challenge I do on my laptop whenever I have time.
- Keeps a real memory of what I've learned and where I struggle, so each lesson builds on the last.

## 2. Key decisions

| Area | Decision |
|---|---|
| Lesson author | Claude Code on my Windows laptop, run without the chat window (`claude -p`), signed in with my Claude Pro account. **No Anthropic API key.** |
| Lesson trigger | **Windows Task Scheduler** on the laptop, not the server. The server can't reach my laptop directly from the internet, so the laptop starts each run. |
| Laptop availability | Laptop stays on. Task Scheduler is set to wake it from sleep and to run a missed task as soon as possible. |
| Schedule | **Weekdays only** (Mon–Fri). Lessons at **10:00, 12:00, 15:00, 17:00** (UK time). Nothing in the evening or at weekends. |
| Coding challenge | Generated by the 17:00 run and saved as `coding-challenge.md` in the learning folder. Not sent to Telegram. I open it in Claude Code whenever I have time and work through it there. |
| Lesson topics | **Two tracks only for now: AI development and data engineering.** Lessons alternate between the two, and each track continues where it left off. |
| Lesson format | See section 3. One small concept per lesson, at most 2–3 short paragraphs, explained as simply as possible. |
| Delivery channel | A Telegram bot (made with BotFather). One chat for everything. |
| Telegram receiving | **Long polling.** The server asks Telegram for new messages. It's free and reliable, and Telegram doesn't need a public HTTPS address. |
| Follow-up Q&A | Handled by the **server using my OpenAI API key**, not Claude. Each call gets only: system prompt + the current lesson + that lesson's Q&A so far. |
| Q&A model | OpenAI's mid-tier model, the equivalent of Claude Sonnet rather than the top model: currently **`gpt-6.1-sol`**. Set in an environment variable so it can be changed without code changes. |
| Server | My existing **AWS Lightsail** instance, running the app in **Docker** (Docker Compose). Uses a Lightsail **static IP**, which is free while attached. |
| HTTPS | Free, no domain to buy: **Caddy** in front of the app, with an automatic **Let's Encrypt** certificate for a free **sslip.io** hostname based on the static IP (e.g. `1-2-3-4.sslip.io`). Amazon's free certificates only attach to a Lightsail load balancer or CDN distribution and still need a domain, so they aren't used. |
| Database | **SQLite** file on Lightsail, kept on a Docker volume. **No Neon.** |
| Claude's memory | Markdown files in the `learning/` folder of the repo (see section 5). |
| Code + memory location | One **private GitHub repo**, cloned on the laptop at `Desktop\Ayush@Strath\Work\Personal Claude Magic\Works\learning-bot`. |
| Deploys | On push to `main` that changes server files, a **GitHub Action SSHes into Lightsail**, runs `git pull`, and rebuilds/restarts the Docker container. Fully automatic. |
| Cloud features | **Not used**: no Claude cloud scheduled tasks, no Claude channels, no Notion. |

## 3. Lesson format

- **One small concept per lesson.** Each lesson covers one bite-sized idea I can read, understand and move on from.
- **Maximum 2–3 short paragraphs.** Readable in a minute or two on my phone.
- **Simplest possible explanation.** Plain language, one everyday example or analogy, the basics only. No jargon without explaining it.
- **Continuous progression.** Each lesson picks up where that track's previous lesson stopped, so the lessons form a running course rather than random topics.
- **Two tracks, alternating:** AI development and data engineering.
- **Adapts to me.** If my questions on a lesson show I didn't get something, a later lesson revisits it.
- Deeper detail is left for my follow-up questions in Telegram.

## 4. Components

### 4.1 Laptop (Windows)
- **Learning folder:** `learning/` inside the repo. It's Claude's working directory, with the memory files and the teaching instructions (`CLAUDE.md`).
- **Lesson script** (PowerShell), run by Task Scheduler at each lesson time:
  1. Calls the server's logs endpoint to fetch any new Q&A since the last sync, and saves it into `learning/logs/`.
  2. Runs `claude -p "<lesson prompt>"` in the learning folder. Claude reads the memory files and new logs, updates `progress.md`/`weak-spots.md`, writes the next lesson, and prints the lesson text.
  3. Posts the lesson text to the server's lesson endpoint.
  4. At 17:00 only, also writes `coding-challenge.md`.
  5. Commits and pushes the updated `learning/` files to GitHub as a backup. This doesn't trigger a deploy (see 4.4).
- **Task Scheduler entries:** weekdays at 10:00, 12:00, 15:00, 17:00, with wake-from-sleep and run-if-missed turned on.
- **Tool permissions:** the `claude -p` call is allowed to read/write files in the learning folder only, so it never stalls on a permission prompt.

### 4.2 Server (Lightsail, Docker)
A small Python app with three jobs:

1. **Receive lessons:** an endpoint the laptop posts each new lesson to. The server saves it in SQLite, sends it to Telegram, marks it as the current open lesson, and closes the previous one.
2. **Telegram bot (long polling):** receives my messages.
   - A normal message is treated as a question about the current lesson.
   - A Telegram *reply* to an older lesson message is treated as a question about that lesson.
   - It calls OpenAI with system prompt + that lesson + that lesson's Q&A, sends the answer back, and stores both in SQLite.
   - Each lesson message has a **"✅ Done" button** that closes that lesson's conversation.
3. **Serve logs:** an endpoint the laptop calls to fetch Q&A since the last sync.

Both laptop-facing endpoints are protected by a shared secret token and served over HTTPS through Caddy.

### 4.3 Data (SQLite)
- **lessons:** id, Telegram message id, track (AI development / data engineering), lesson text, sent time, status (open/closed).
- **messages:** id, lesson id, role (me/assistant), text, time.
- The laptop's `learning/logs/` folder, pushed to GitHub, also acts as a backup of this data.

### 4.4 GitHub & deploys
- One private repo for code and memory.
- GitHub Action on push to `main`, **only when `server/` or deploy files change**: SSH into Lightsail → `git pull` → `docker compose up -d --build`. Memory-only pushes from the lesson script don't redeploy.
- Secrets kept in GitHub Actions secrets and in a `.env` on the server, never committed: Telegram bot token, OpenAI API key, OpenAI model name, shared laptop↔server token, Lightsail SSH key.

## 6. Flows

**Lesson (weekdays 10/12/15/17):**
Task Scheduler → lesson script → fetch new Q&A from server → `claude -p` writes lesson + updates memory → post lesson to server → server sends to Telegram → becomes the open lesson → memory pushed to GitHub.

**Question:**
I message the bot → server finds the lesson (current, or the one I replied to) → OpenAI call with system prompt + lesson + its Q&A → answer to Telegram → saved in SQLite.

**Close:**
Tap "✅ Done" on a lesson, or the next lesson arrives → that conversation closes → the next question starts fresh with the new lesson.

**Coding challenge:**
The 17:00 run writes `coding-challenge.md` → I open it in Claude Code whenever I like and work through it with Claude.

**Deploy:**
Edit server code on laptop → push to GitHub → Action deploys to Lightsail automatically.
